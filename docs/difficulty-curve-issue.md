# chess-az 難度曲線要修：自訂難度中低段太弱、像亂走

> 交接給 chess-az（Ubuntu）session。這是**網頁版通病**（`serve_az.py`），桌面版只是包網頁版，
> 改一處兩邊同時好。

## 症狀
自訂難度設 50（甚至把 sims 拉到 400）AI 還是下得又弱又雜，看起來像亂走。
**不是隨機 bug、不是打包問題**：`z_select_move` 的方案 A（依 MCTS 訪問排名挑第 N 好步）有正常運作，
是**難度→名次曲線設計讓 50 太弱**。

## 根因
`alphazero/serve_az.py` 的 `z_select_move` 用線性名次：
```python
s = _z01(z)                      # 實際上 s ≈ 難度/100
center = (1.0 - s) * (k - 1)     # 線性 → 難度50 挑第 ~(k-1)/2 名（中段）
```
`difficulty_to_z(1~100)` 線性映到 z∈[-2,2]，所以 `s ≈ 難度/100`。
難度 50 → 挑中段名次，但 MCTS 訪問數集中在好步，**中段名次 = 爛步** → 弱且雜。
棋力幾乎全擠在 80~100，50 以下都偏弱。

## 實測證據（v0.6 桌面 exe，人走中炮 h2e2 後 AI 6 次回手）
| 難度 | AI 回手 | 判讀 |
|---|---|---|
| 100 | h9g7 ×5、b9c7 ×1 | 強且穩定（跳馬） |
| 50 | h9i7 / f9e8 / g9e7 / d9e8（4 種） | 弱且雜（士象邊角步）← 使用者看到的「亂走」 |
| 1 | c6c5 ×4 / h7c7 / b7b6 | 弱（推兵/平炮） |

## 建議修法（曲線拉陡：多數滑桿接近最佳步、只有低端放水）
`z_select_move` 內把線性 center 改成冪次（exponent 2~3 可調）：
```python
center = (1.0 - s) ** 3 * (k - 1)
```
效果：
- 難度 100 → 第 0 名（最佳）
- **難度 50 → 第 ~4 名（高手級、穩健，不再亂走）**
- 難度 25 → 第 ~12 名（中等偏弱）
- 難度 1 → 最差步

`spread` 那行維持現狀即可（強端窄穩、弱端寬）。
或者改成非線性的 `difficulty_to_z` 讓 z 隨難度非線性上升，擇一即可。

## 影響範圍
只改 `serve_az.py` 一處：
- **線上網頁版**：直接生效。
- **桌面版**：有自動 CI（`.github/workflows/build-desktop-px0.yml`），dev 一 push 到 `serve_az.py`
  就自動重建三平台 `desktop-latest` release，**不用碰打包**。
