# 自訂難度演算法演進記錄（chess-az）

> 記錄「自訂難度」選步演算法從**交大（NCTU 吳毅成）z-index 線性棋力系統**一路到現行
> **方案 A（挑第 N 好步 + 冪次曲線）**的每一次改動與**為什麼**。
> 主檔：`alphazero/serve_az.py` 的 `z_select_move()` / `resolve_difficulty()`。
> 適用線上網頁版與桌面版（桌面只是包網頁版，改一處兩邊同時好）。

---

## 名詞
- **MCTS 訪問分佈**：搜尋跑完後，root 各合法著法被模擬造訪的次數 `N_i`；好步被造訪多、爛步少或 0。
- **sims**：每步的模擬（搜尋）次數，越多越強越慢。
- **px0 網路**：借來的強策略/價值網路（見 `docs/HANDOFF.md`），棋感很強。

---

## 階段 0：交大 z-index 線性棋力系統（原始做法，chess-test 就有）
- 出處：NCTU 吳毅成團隊論文的「棋力可調」系統，主線 Rust 版 `engine::best_move_mcts_strength` 已實作。
- 做法：難度 1~100 → 線性映射 strength index `z ∈ [-2, 2]`（`difficulty_to_z`）。
  跑完 MCTS 後，對訪問數做 **π_i ∝ N_i^z** 的加權抽樣選步；並先用門檻 `R_th`
  濾掉 `N_i < N_max·R_th` 的爛步。
- 直覺：`z` 大 → 偏向高訪問（強）；`z=0` → 均勻；`z<0` → 偏向低訪問（弱）。z↔Elo 近線性。
- **為什麼採用**：使用者硬需求要用這套（論文可調棋力），且與 chess-test 一致。

## 階段 1：移植到 chess-az（px0 版）
- `serve_az.py` 用 px0 網路 + 自家 PUCT MCTS，`z_select_move` 照抄 π∝N^z + R_th。
- 固定 `sims`。
- **問題浮現**：怎麼調都偏強、弱不太下來（伏筆，見階段 4）。

## 階段 2：sims 與門檻隨 z 縮放（想拉開強弱範圍）
- 動機：使用者指出「要 sims 夠強、再配門檻調低，下限才會更弱」。
- 改動：
  - `sims_for_z`：z=-2→40、z=+2→160（弱端少＝快又弱、強端多＝強且分佈細）。
  - `rth_for_z`：z=-2→0（放行爛步）、z=+2→0.10（保品質）。
- **為什麼**：sims 決定天花板+粒度、R_th 決定下限；兩者一起動才拉得開。

## 階段 3：獨立 sims 拉霸 + 即時生效
- 使用者要 sims 能獨立手動調、且不必重開局。
- 改動：自訂模式前端兩支拉霸（棋力 z + 模擬數 sims）；每步 WS 都帶 `difficulty`+`sims`，
  `serve_az` 在每步 `move` 時 `resolve_difficulty` 重新解析 → 中途調拉霸下一步即生效。
- `sims` 有給就用滑桿值，沒給才依 z 縮放。

## 階段 4：發現「弱端弱不下來」的根因，一次失敗嘗試（已回退）
- 症狀：棋力調到 1、sims 拉到 400，AI 還是很強。
- **根因**：px0 策略網路太準，把爛步的訪問壓到 0、**根本不進候選**；純 π∝N^z 只在
  「被搜到的好步」裡挑，z 再負也選不到真正的爛步 → 這是「強神經網路 + 論文 z」的先天限制。
- 嘗試（commit 97fc7b5）：選步 = `(1-w)·搜尋分佈 + w·全合法均勻`，w=1-z01(z)。
  弱端幾乎均勻亂抽 → 真的會送子。
- **使用者否決、已 revert（e33837f）**：純亂數「只有隨機、沒有『很弱 vs 比較弱』的層次」。
- **教訓**：弱化要有**層次**（下軟手/次佳步），不是注入亂數。

## 階段 5：方案 A — 挑第 N 好步（現行）
- 使用者在 A/B 兩案中選 A。
- 做法（`z_select_move`）：把**搜尋過的**著法依訪問數由好到壞排序，依棋力挑「第 r 名」：
  - 強 → r≈0（最佳步）；弱 → r≈最後（搜尋過的最差步）。
  - `r` 用常態分佈 `random.gauss(center, spread)` 在目標名次附近取樣（自然變化），再夾到 `[0, k-1]`。
- **為什麼**：全程都是網路算過的合理著法 → 弱是「有邏輯的臭棋/軟手」而非亂數，且名次給了平滑梯度。

## 階段 6：難度→名次曲線由線性改冪次（修中低段太弱像亂走）
- 症狀（見 `docs/difficulty-curve-issue.md`）：難度 50 仍又弱又雜像亂走。
- **根因**：線性 `center=(1-s)·(k-1)` 讓難度 50 挑「中段名次」，但訪問集中在好步，
  **中段名次其實已是爛步** → 50 太弱。棋力幾乎全擠在 80~100。
- 改動（commit 0b17bbc）：曲線拉陡（冪次）
  ```python
  s = _z01(z)            # ≈ 難度/100，1=最強
  d = 1.0 - s
  center = (d ** 3) * (k - 1)                # 大部分滑桿貼最佳步，只有低端才放水
  spread = (d ** 2) * (k - 1) * 0.25 + 0.5   # 中高段窄(穩)、低端才寬
  r = clamp(round(gauss(center, spread)), 0, k-1)
  ```
- 實測平均名次（0=最佳，起手局 k≈10）：
  | 難度 | 平均名次 | 判讀 |
  |---|---|---|
  | 100 | 0.2 | 最佳、穩 |
  | 75 | 0.4 | 接近最佳 |
  | 50 | 1.3 | 高手級穩健（修好，不再亂走） |
  | 25 | 4.0 | 中等偏弱 |
  | 1 | 7.7 | 軟手（搜尋過的最差步） |

## 現行摘要（TL;DR）
- 難度 1~100 → `z`（線性）→ `s=_z01(z)≈難度/100`。
- 自訂 sims：滑桿獨立控制（沒給則依 z 縮放）；每步即時生效。
- 選步：MCTS 訪問排序好→壞，依 `center=(1-s)³·(k-1)` 挑第 r 名、`spread=(1-s)²·…` 常態抖動。
- 預設 簡單/中等/困難 = 固定 sims、取訪問最高步（不走 z）。

## 已知限制 / 可再調
- 起手/中局搜尋過的步不多（k 小），最弱大概是「第 8~10 好」的軟手；若要最底更爛，可放寬弱端候選（納入未搜尋步）或降 exponent。
- exponent（現 3）與 spread 係數都可調棋感。
